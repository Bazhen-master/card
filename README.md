# Метафорические карты — пилотный проект

## Структура проекта

- `app/` — страницы сайта (Next.js App Router)
  - `page.js` — главная страница
  - `catalog/` — каталог колод и страница отдельной колоды
  - `generate/` — генерация своей карты через нейросеть (Этап 3)
  - `admin/` — личный кабинет: управление колодами и картами
  - `api/admin/` — вход и выход из админки
- `components/` — переиспользуемые UI-блоки
- `lib/` — клиент Supabase, авторизация, загрузка файлов, форматирование
- `supabase/schema.sql` — SQL-схема базы (выполняется один раз в Supabase)
- `middleware.js` — защита `/admin/*` паролем

## Выбор платформы и хостинга

- **Платформа:** Next.js (React) — быстрая сборка MVP, легко расширяется под будущие
  этапы без переписывания с нуля.
- **База данных и хранилище картинок:** Supabase (Postgres + Storage). Файловая
  система хостинга между перезапусками не сохраняется, поэтому картинки хранятся
  в Supabase Storage.
- **Хостинг:** Timeweb Cloud, раздел App Platform — российская площадка, оплата
  рублёвой картой, деплой из GitHub. Выбран после того, как Render перестал
  открываться у заказчицы из России: у зарубежных площадок доступность российской
  аудитории от нас не зависит и не гарантирована.
- **Картинки идут через наш домен.** В вёрстке `<img src>` указывает на
  `/api/image/<файл>`, а не на `supabase.co`: браузер посетителя обращается только
  к нашему сайту, а файл из Storage забирает сервер. Иначе при недоступности
  Supabase из России страница открывалась бы без изображений.

## Подключение Supabase

1. Зарегистрируйтесь на [supabase.com](https://supabase.com), создайте проект
   (регион — ближайший, например Frankfurt).
2. Откройте **SQL Editor → New query**, вставьте содержимое файла
   `supabase/schema.sql` и нажмите **Run**. Скрипт создаст таблицы `decks`,
   `cards`, `leads` и публичный бакет `cards` для картинок.
3. Откройте **Project Settings → API** и скопируйте оттуда:
   - **Project URL** → в переменную `SUPABASE_URL`
   - **service_role** ключ → в переменную `SUPABASE_SERVICE_ROLE_KEY`

> `service_role` — секретный ключ с полным доступом к базе. Он используется
> только на сервере и никогда не попадает в браузер. Не публикуйте его и не
> коммитьте в git.

## Переменные окружения

Локально — файл `.env.local` (см. образец `.env.local.example`, в git не попадает).
На хостинге — раздел **Переменные окружения** в панели Timeweb Cloud.

```
SUPABASE_URL=                  # Project URL из Supabase
SUPABASE_SERVICE_ROLE_KEY=     # service_role ключ из Supabase
ADMIN_PASSWORD=                # пароль для входа в /admin
GENAPI_KEY=                    # Этап 3, ключ gen-api.ru
COMMISSION_PERCENT=            # необязательно: комиссия площадки, по умолчанию 30
```

Пока переменные не заданы, сайт продолжает работать: каталог и админка
показывают подсказку о том, что база не подключена, вместо ошибки.

## Как запустить локально

```bash
npm install
cp .env.local.example .env.local   # затем заполнить значения
npm run dev
```

Сайт будет доступен на http://localhost:3000

## Админка

- Адрес: `/admin`, вход по паролю из `ADMIN_PASSWORD`.
- Сессия хранится в httpOnly-cookie и живёт 12 часов, дальше — повторный вход.
- Возможности: создание колод (название, описание, цена, обложка), загрузка карт
  (можно выбрать сразу несколько файлов), редактирование текста и цены карты,
  замена изображения, удаление, порядок отображения кнопками ↑ / ↓.
- При удалении колоды удаляются и её карты, и все связанные файлы в Storage.
- Ограничение на размер одной отправки формы — 25 МБ. Если карт много, загружайте
  их партиями по несколько штук.

## Генерация карт (Kandinsky)

Раздел `/generate`: посетитель описывает карту словами, выбирает формат и стиль и
получает картинку. Результат сохраняется как карта с `source_type = 'generated'` и без
привязки к колоде — в каталог такие карты не попадают.

**Кто рисует.** С 07.09.2026 — [GenAPI](https://gen-api.ru), модель Flux. От
FusionBrain (Kandinsky) отказались: дорого при слабом качестве картинок. Клиент
FusionBrain остался в репозитории как запасной вариант.

**Ключ.** Регистрация на [gen-api.ru](https://gen-api.ru) → пополнить баланс
российской картой → личный кабинет, раздел ключей API → создать ключ:

```
GENAPI_KEY=
```

Ключ один на весь каталог моделей — отдельно ни за что подписываться не нужно,
деньги списываются по факту генерации.

**Сколько стоит.** 0,50 ₽ за картинку на Flux Schnell — проверено настоящим
списанием 07.09.2026 при размере 768×1024 (колода из 60 карт — около 30 ₽).

> Ценам в каталоге `GET /api/v1/networks` и на витрине gen-api.ru/pricing верить
> нельзя: там базовая ставка сети, а не цена запуска. Для `flux` каталог обещает
> 4,5 ₽, списывается 0,50 ₽; для `sdxl` обещает 0,5 ₽, списывается 1,38 ₽.
> Настоящая цена — поле `cost` в ответе `GET /api/v1/request/get/{id}` после
> генерации.

Если качество не устроит, модель меняется переменной окружения, код трогать
не нужно:

```
GENAPI_MODEL=schnell     # по умолчанию, 0,50 ₽ за картинку
GENAPI_MODEL=dev         # промежуточный вариант
GENAPI_MODEL=pro         # дороже, максимальное качество
```

Баланс предоплаченный: когда деньги кончатся, страница генерации скажет об этом
прямо, а остальной сайт продолжит работать. Неожиданного счёта прийти не может.

**Перевод описания.** Описание посетителя перед отправкой в Flux переводится на
английский самой дешёвой моделью каталога (0,003 ₽ за запрос) — по-английски
модель понимает точнее и реже добавляет от себя лишнее вроде подписи художника
в углу. Русский Flux тоже понимает, так что при отказе перевода генерация всё
равно идёт, по исходному тексту, а причина пишется в лог хостинга. Выключить
перевод: `GENAPI_TRANSLATE_MODEL=` (пустое значение). Итоговое описание, которое
ушло в нейросеть, тоже пишется в лог — по нему видно, почему карта вышла такой.

**Что уходит в нейросеть.** К описанию посетителя всегда добавляется общий хвост:
что это метафорическая ассоциативная карта для работы психолога — образ, который
специалист показывает клиенту, чтобы начать разговор о чувствах, допускающий разные
прочтения, без надписей, подписей и рамки. Без такого пояснения Flux рисует просто
красивую картинку: буквальную, перегруженную деталями и нередко с подписью в углу.
Текст хвоста — `BASE_PROMPT` в `lib/providers/genapi.js`.

**Формат карты.** Три варианта в форме: вертикальный 768×1024 (по умолчанию, как в
готовых колодах), горизонтальный 1024×768 и квадрат 1024×1024. Список — `FORMATS` в
`lib/image-provider.js`, стороны кратны 32, этого требует Flux. Результат
показывается в своей пропорции, а не обрезается под 3:4. Проверено живым ключом
07.09.2026: обе новые пропорции приходят ровно такими, как заказаны, цена та же.

**Как сменить нейросеть целиком.** Переменная `IMAGE_PROVIDER`: `genapi` (по
умолчанию) или `fusionbrain`. Поставщики лежат в `lib/providers/`, страницы знают
только про `lib/image-provider.js` — добавить третьего значит написать один файл с
методами `missingEnv` и `generateImage`.

Пока ключа нет, страница показывает подсказку и называет недостающие переменные —
остальной сайт работает как обычно.

**База.** После обновления нужно один раз выполнить `supabase/schema.sql` в
Supabase → SQL Editor → New query: скрипт добавит таблицу `generations`, по которой
считается лимит. Повторный запуск существующие таблицы не трогает. Пока таблицы нет,
страница прямо об этом говорит.

**Лимит.** 5 генераций в сутки на посетителя (случайный id в httpOnly-cookie) и 20
в сутки на один адрес.

> Уточнение от 07.09.2026: после перехода на GenAPI общий месячный потолок на весь
> сайт больше не нужен — там нет месячной квоты, есть предоплаченный баланс, и он же
> служит естественным потолком расходов. Сутки максимальной нагрузки на Flux Schnell
> стоят порядка 10 ₽ на посетителя. Адрес не хранится — в таблицу идёт только его хеш. Значения
лежат в `lib/generation-limit.js`, менять их можно там. Полноценных аккаунтов на
этом этапе нет, поэтому лимит по cookie обходится очисткой браузера — второй рубеж
по адресу существует ровно для того, чтобы это не превращалось в расход бюджета.

**Переменные `GENAPI_API_URL` и `FUSIONBRAIN_API_URL`** задавать не нужно: они
существуют только для локальной проверки на заглушке, чтобы не тратить оплаченные
генерации. Без них используется адрес настоящего API.

## Учётные записи посетителей

Появились на Этапе 6.1. Без входа сайт работает как раньше: каталог, генерация
по суточному лимиту, история карт в cookie. Учётная запись нужна, чтобы карты
не терялись вместе с историей браузера, — и дальше на неё лягут галерея,
покупки и баланс.

**Как устроено.** Пароли хранит и проверяет Supabase Auth (`auth.users`), свой
велосипед не пишем. Подтверждение почты выключено намеренно: письма слать пока
нечем, поэтому запись создаётся служебным ключом сразу подтверждённой. Проверка
пароля тем же служебным ключом работает — отдельный публичный ключ Supabase не
нужен, новых переменных окружения этап не добавил.

**Сессия своя, а не токен Supabase.** Таблица `sessions`: cookie `mc_account`
хранит только случайный номер строки, срок — 30 суток. Так доступ закрывается
мгновенно, удалением строки, чего с токеном не сделать. Заодно каждая новая
сессия подчищает протухшие.

**Минимальная длина пароля — 8 символов, проверяется на нашей стороне.** У
Supabase своей нижней границы нет: проверено живым ключом, пароль «123» он
принимает.

**Что видит вошедший.** `/account` — почта, свои карты, кнопка «Выйти».
История генераций у него берётся из аккаунта, а не из cookie, и суточный лимит
считается тоже по аккаунту: очистка cookie его больше не обнуляет. Карты,
нарисованные до регистрации, переносятся в аккаунт при первом входе.

**Чего пока нет.** Восстановления пароля (нужен свой почтовый сервис),
подтверждения адреса, входа через Telegram или VK. Ссылка на политику
обработки персональных данных в форме регистрации появится, когда заказчица
пришлёт текст, — сейчас там короткое пояснение своими словами.

**База.** После обновления один раз выполнить `supabase/schema.sql` (Supabase →
SQL Editor → New query). Скрипт идемпотентный: добавит `profiles`, `sessions`,
колонку `cards.owner_id` и `generations.profile_id`, существующее не тронет.

## Водяной знак и оригиналы карт

Появились на Этапе 6.2. Смысл: показывать чужую карту можно, отдавать её
даром — нет.

**Два файла на карту.** Оригинал уходит в закрытый бакет `cards-private`, у
которого нет публичных ссылок вообще. Рядом, в публичном `cards`, ложится
превью: уменьшенная до 700 px копия с водяным знаком. В `cards.image_url`
для оригинала хранится не ссылка, а пометка `private://<файл>`.

**Знак накладывается на сервере** библиотекой `sharp` и становится частью
пикселей. Полупрозрачный логотип поверх картинки в вёрстке — не защита: такой
слой снимается в браузере за десять секунд.

**Сама надпись лежит готовой картинкой** — `public/watermark.png`, повторяется
плиткой по всей площади. Рисовать текст на сервере нельзя: в контейнере может
не быть ни одного шрифта, и надпись вышла бы пустотой. Когда заказчица
согласует логотип, достаточно заменить этот файл — код не меняется. Плитка
рисуется скриптом из `sharp` на машине разработчика.

**Кто видит оригинал.** Маршрут `/api/original/<id карты>` проверяет, кто
спрашивает: владелец карты, гость, нарисовавший её в своей сессии,
администратор — и, начиная с Этапа 6.4, покупатель. Остальным ответ 403 и
превью со знаком. Ссылка с `?download` отдаёт файл на скачивание — эта кнопка
есть в кабинете под своими картами.

**Если `sharp` не соберётся на хостинге**, генерация не сломается: карта
сохранится, превью не будет, причина уйдёт в лог. Такую карту нельзя выставить
в галерею — и это правильное поведение, а не полумера.

**База.** Нужны колонка `preview_url` в `cards` и закрытый бакет
`cards-private` — оба есть в `supabase/schema.sql`.

## Галерея и модерация

Появились на Этапе 6.3. Автор выставляет свою карту в общую галерею, владелица
сайта пропускает её или отклоняет с причиной.

**Путь карты:** `private` (лежит в кабинете) → `pending` (отправлена на
проверку) → `listed` (в галерее) либо `rejected` (отклонена, причина видна
автору). Статус хранится в `cards.status`.

**Кабинет** `/account`: под каждой картой — её статус и действия. Выставить с
ценой, отозвать с проверки, убрать с витрины. Там же поле «Имя автора»: оно
стоит под картами в галерее, почта посетителям не показывается.

**Галерея** `/gallery`: только `listed`, с водяным знаком. Чужой черновик по
прямой ссылке не открывается — страницы неопубликованной карты не существует
ни для кого, кроме её автора.

**Модерация** `/admin/moderation`: очередь с превью, автором, ценой и ссылкой
на оригинал без знака. «Отклонить» требует причины — автор должен понимать,
что исправить. В админке рядом со ссылкой висит счётчик очереди.

**Цены хранятся в копейках.** Причина: комиссия площадки в 30 % с карты за 3 ₽
в целых рублях не считается. В формах и на витрине — рубли, дробные цены
разрешены с шагом в десятую (1,4 ₽ — 140 копеек). Лишние нули не показываются:
«3 ₽», «3,5 ₽», «3,05 ₽». Минимальная цена карты — 3 ₽ (`MIN_CARD_PRICE` в
`lib/format.js`).

Перевод старых цен из рублей в копейки выполнен разово 07.09.2026 и в
`supabase/schema.sql` намеренно не повторяется: повторный запуск умножил бы их
ещё раз.

## Баланс и покупки

Появились на Этапе 6.4. Живых денег на сайте пока нет: внутри ходят баллы,
цена которых равна рублю.

**Журнал — источник правды.** Отдельного числа «остаток» в базе нет: баланс
равен сумме `balance_entries.delta`. Так расхождение «на счету 12 ₽, а по
операциям 9 ₽» невозможно, и любой спор с автором разбирается по строкам.
Виды операций: пополнение, покупка, продажа, генерация, возврат, корректировка.

**Покупка** списывает цену с баланса покупателя и начисляет автору его долю.
Комиссия площадки — 30 % (`COMMISSION_PERCENT`, меняется переменной окружения),
**остаток при делении идёт автору**: с карты за 3,5 ₽ площадке 1,05 ₽, автору
2,45 ₽. Купленная карта сразу открывается без водяного знака и скачивается.

**Настоящей транзакции нет** — сайт ходит в базу по REST, а не по SQL. Порядок
выбран так, чтобы осечка была видна и откатывалась: сначала запись о покупке
(её защищает уникальный индекс — дважды одну карту не купить), потом списание,
потом перепроверка баланса, и только затем начисление автору. Уйти в минус
нельзя: при отрицательном балансе списание и покупка удаляются. Если не прошло
последнее начисление автору, в лог уходит строка «НАЧИСЛЕНИЕ АВТОРУ НЕ ПРОШЛО»
с суммой — её начисляют руками из админки.

**Пополнение — вручную.** `/admin/users`: список зарегистрированных с их
балансом, поле «Сумма, ₽» (отрицательная — списание) и комментарий, который
увидит пользователь в кабинете. Там же блокировка: она гасит и активные сессии,
и вход. Автоматическое пополнение через ЮKassa — Этап 7, для него нужны ИП или
самозанятость, договор и чеки по 54-ФЗ.

**В кабинете** посетитель видит баланс, последние 20 операций и купленные карты
со ссылками на скачивание.

## Деплой на Timeweb Cloud

Аккаунт оформляется на заказчицу: площадка платная, деньги списываются с её карты,
и сайт должен остаться на её аккаунте, а не на аккаунте разработчика.

### Шаг 1. Регистрация и баланс — делает заказчица

1. [timeweb.cloud](https://timeweb.cloud) → **Регистрация**, указать свою почту.
2. Пароль придумать **новый, только под этот проект**: его придётся передать
   разработчику для настройки, поэтому пароль, который используется где-то ещё,
   не подходит.
3. Подтвердить почту по письму.
4. Пополнить баланс: раздел **Баланс** → **Пополнить**. На первый месяц хватит
   500 ₽, тариф под этот сайт — примерно 300–600 ₽/мес.
5. Передать разработчику почту и пароль (удобнее двумя отдельными сообщениями).

После настройки пароль можно сменить: сайт пересобирается сам по коммитам в GitHub,
постоянный доступ к панели разработчику не нужен.

### Шаг 2. Создание приложения

1. В меню слева откройте **App Platform** и нажмите **Создать**.
2. Тип приложения — **Next.js**, версия Node.js — **22**.
3. Нажмите **Подключить аккаунт** у GitHub, разрешите доступ, выберите репозиторий
   `Bazhen-master/card` и ветку `main` → **Save**.
4. Включите **поддержку SSR**. Это обязательно: страницы читают базу на сервере, без
   SSR каталог и админка работать не будут. Выключить потом нельзя — только создавать
   приложение заново, поэтому проверьте этот переключатель до запуска.
5. Проверьте команды (обычно подставляются сами):
   - **Сборка:** `npm ci && npm run build`
   - **Запуск:** `npm start`
6. В разделе **Переменные окружения** добавьте три штуки, значения возьмите из своего
   `.env.local`:
   - `SUPABASE_URL` — Project URL из Supabase
   - `SUPABASE_SERVICE_ROLE_KEY` — секретный ключ из Supabase
   - `ADMIN_PASSWORD` — пароль для входа в `/admin`
7. Убедитесь, что стоит **Сборка по последнему коммиту** — тогда сайт пересобирается
   сам при каждом `git push`.
8. Нажмите **Запустить деплой**. Первая сборка занимает 3–5 минут, после неё в
   настройках приложения появится публичный адрес.

Порт задавать не нужно: `npm start` слушает порт из переменной `PORT`, её подставляет
платформа.

### Шаг 3. Проверка

Открыть сайт из России может только заказчица — попросите её зайти по адресу без VPN
и подтвердить, что видны каталог и картинки колод.

> Если сайт открылся, но пишет «База данных ещё не подключена» — он назовёт
> недостающие переменные прямо на странице. Добавьте их в **Переменные окружения**
> и пересоберите приложение.

### Если в логах SIGTERM

Такой лог **не означает ошибку запуска**:

```
✓ Ready in 482ms
npm error signal SIGTERM
npm error command failed
```

`Ready` — приложение поднялось нормально. `SIGTERM` — платформа сама попросила
его завершиться, а `npm error` следом это лишь пересказывает. Так выглядит
обычная остановка контейнера: при выкладке нового коммита старый контейнер
гасится именно так.

Тревожно, только если эти строки повторяются раз за разом — тогда приложение
перезапускается по кругу. Что смотреть:

1. Откройте `https://<адрес-сайта>/api/health`. Он отвечает `200` и JSON, ничего
   не читая из базы. Если ответ есть — приложение живо, дело не в запуске.
   В ответе видно, заданы ли переменные окружения.
2. Если у приложения настроена проверка доступности (health check), укажите ей
   путь `/api/health`. На пути, который ходит в базу, недоступность Supabase
   выглядит как «приложение сломалось», и платформа уводит его в перезапуск.
3. Проверьте лимит памяти тарифа: Next.js в проде занимает около 300 МБ.

Порт задавать не нужно: `npm start` слушает порт из переменной `PORT` и
принимает соединения со всех интерфейсов (`-H 0.0.0.0`) — иначе прокси
платформы не достучался бы до приложения.

### Адрес админки

Админка живёт по адресу вашего сайта с `/admin` на конце:

```
https://<адрес-приложения>.twc1.net/admin
```

Точный адрес показан в панели Timeweb Cloud, в настройках приложения. Открывается
страница входа, пароль — значение переменной `ADMIN_PASSWORD`.

> Если после ввода пароля браузер уходит на `localhost:3000/admin` — это была
> ошибка в коде редиректов (приложение за прокси не видит настоящий домен).
> Исправлено; нужно, чтобы на хостинге стояла сборка от 6 сентября 2026 или новее.

### Render — запасной вариант

`render.yaml` остаётся в репозитории, и Render по-прежнему поднимет сайт через
**New → Blueprint**. Но как основную площадку его больше не рассматриваем:
доступность из России не гарантирована, а на бесплатном тарифе сервис засыпает и
первый запрос ждёт запуска 30–50 секунд.
