# Метафорические карты — пилотный проект

## Структура проекта

- `app/` — страницы сайта (Next.js App Router)
  - `page.js` — главная страница
  - `catalog/` — каталог колод и страница отдельной колоды
  - `generate/` — генерация своей карты через нейросеть (Этап 3)
  - `admin/` — личный кабинет: управление колодами и картами
  - `api/admin/` — вход и выход из админки
- `components/` — переиспользуемые UI-блоки
- `lib/` — клиент Supabase, авторизация, загрузка файлов, форматирование
- `supabase/schema.sql` — SQL-схема базы (выполняется один раз в Supabase)
- `middleware.js` — защита `/admin/*` паролем

## Выбор платформы и хостинга

- **Платформа:** Next.js (React) — быстрая сборка MVP, легко расширяется под будущие
  этапы без переписывания с нуля.
- **База данных и хранилище картинок:** Supabase (Postgres + Storage). Файловая
  система хостинга между перезапусками не сохраняется, поэтому картинки хранятся
  в Supabase Storage.
- **Хостинг:** Timeweb Cloud, раздел App Platform — российская площадка, оплата
  рублёвой картой, деплой из GitHub. Выбран после того, как Render перестал
  открываться у заказчицы из России: у зарубежных площадок доступность российской
  аудитории от нас не зависит и не гарантирована.
- **Картинки идут через наш домен.** В вёрстке `<img src>` указывает на
  `/api/image/<файл>`, а не на `supabase.co`: браузер посетителя обращается только
  к нашему сайту, а файл из Storage забирает сервер. Иначе при недоступности
  Supabase из России страница открывалась бы без изображений.

## Подключение Supabase

1. Зарегистрируйтесь на [supabase.com](https://supabase.com), создайте проект
   (регион — ближайший, например Frankfurt).
2. Откройте **SQL Editor → New query**, вставьте содержимое файла
   `supabase/schema.sql` и нажмите **Run**. Скрипт создаст таблицы `decks`,
   `cards`, `leads` и публичный бакет `cards` для картинок.
3. Откройте **Project Settings → API** и скопируйте оттуда:
   - **Project URL** → в переменную `SUPABASE_URL`
   - **service_role** ключ → в переменную `SUPABASE_SERVICE_ROLE_KEY`

> `service_role` — секретный ключ с полным доступом к базе. Он используется
> только на сервере и никогда не попадает в браузер. Не публикуйте его и не
> коммитьте в git.

## Переменные окружения

Локально — файл `.env.local` (см. образец `.env.local.example`, в git не попадает).
На хостинге — раздел **Переменные окружения** в панели Timeweb Cloud.

```
SUPABASE_URL=                  # Project URL из Supabase
SUPABASE_SERVICE_ROLE_KEY=     # service_role ключ из Supabase
ADMIN_PASSWORD=                # пароль для входа в /admin
FUSIONBRAIN_API_KEY=           # Этап 3, пока не используется
FUSIONBRAIN_SECRET_KEY=        # Этап 3, пока не используется
```

Пока переменные не заданы, сайт продолжает работать: каталог и админка
показывают подсказку о том, что база не подключена, вместо ошибки.

## Как запустить локально

```bash
npm install
cp .env.local.example .env.local   # затем заполнить значения
npm run dev
```

Сайт будет доступен на http://localhost:3000

## Админка

- Адрес: `/admin`, вход по паролю из `ADMIN_PASSWORD`.
- Сессия хранится в httpOnly-cookie и живёт 12 часов, дальше — повторный вход.
- Возможности: создание колод (название, описание, цена, обложка), загрузка карт
  (можно выбрать сразу несколько файлов), редактирование текста и цены карты,
  замена изображения, удаление, порядок отображения кнопками ↑ / ↓.
- При удалении колоды удаляются и её карты, и все связанные файлы в Storage.
- Ограничение на размер одной отправки формы — 25 МБ. Если карт много, загружайте
  их партиями по несколько штук.

## Генерация карт (Kandinsky)

Раздел `/generate`: посетитель описывает карту словами, выбирает стиль и получает
картинку. Результат сохраняется как карта с `source_type = 'generated'` и без
привязки к колоде — в каталог такие карты не попадают.

**Ключи.** Нужна регистрация на [fusionbrain.ai](https://fusionbrain.ai), затем
раздел [Ключи API](https://fusionbrain.ai/keys/) — там создаётся пара:

```
FUSIONBRAIN_API_KEY=
FUSIONBRAIN_SECRET_KEY=
```

Тариф уточняется в личном кабинете. Раньше API был бесплатным без заметных
ограничений, в 2025 году доступ урезали: у веб-интерфейса бесплатно 20 изображений в
месяц, дальше подписки (499 ₽ за 200 генераций, 3 499 ₽ за 1 500). По API называется
бесплатный тариф порядка 100 запросов в месяц, но официальную страницу тарифов
проверить не удалось — `fusionbrain.ai` не отвечает на запросы из-за рубежа. Реальную
квоту показывает раздел ключей в кабинете, смотреть надо там.

Пока ключей нет, страница показывает подсказку и называет недостающие переменные —
остальной сайт работает как обычно.

**База.** После обновления нужно один раз выполнить `supabase/schema.sql` в
Supabase → SQL Editor → New query: скрипт добавит таблицу `generations`, по которой
считается лимит. Повторный запуск существующие таблицы не трогает. Пока таблицы нет,
страница прямо об этом говорит.

**Лимит.** 5 генераций в сутки на посетителя (случайный id в httpOnly-cookie) и 20
в сутки на один адрес.

> Требует пересмотра. Эти числа выбирались, когда API считался бесплатным. Если
> месячная квота действительно около 100 генераций, одного активного посетителя
> хватит, чтобы исчерпать её за три дня: нужен ещё общий потолок на весь сайт за
> календарный месяц, а не только ограничение на человека. Адрес не хранится — в таблицу идёт только его хеш. Значения
лежат в `lib/generation-limit.js`, менять их можно там. Полноценных аккаунтов на
этом этапе нет, поэтому лимит по cookie обходится очисткой браузера — второй рубеж
по адресу существует ровно для того, чтобы это не превращалось в расход бюджета.

**Переменная `FUSIONBRAIN_API_URL`** задавать не нужно: она существует только для
локальной проверки на заглушке, чтобы не тратить оплаченные генерации. Без неё
используется адрес настоящего API.

## Деплой на Timeweb Cloud

Аккаунт оформляется на заказчицу: площадка платная, деньги списываются с её карты,
и сайт должен остаться на её аккаунте, а не на аккаунте разработчика.

### Шаг 1. Регистрация и баланс — делает заказчица

1. [timeweb.cloud](https://timeweb.cloud) → **Регистрация**, указать свою почту.
2. Пароль придумать **новый, только под этот проект**: его придётся передать
   разработчику для настройки, поэтому пароль, который используется где-то ещё,
   не подходит.
3. Подтвердить почту по письму.
4. Пополнить баланс: раздел **Баланс** → **Пополнить**. На первый месяц хватит
   500 ₽, тариф под этот сайт — примерно 300–600 ₽/мес.
5. Передать разработчику почту и пароль (удобнее двумя отдельными сообщениями).

После настройки пароль можно сменить: сайт пересобирается сам по коммитам в GitHub,
постоянный доступ к панели разработчику не нужен.

### Шаг 2. Создание приложения

1. В меню слева откройте **App Platform** и нажмите **Создать**.
2. Тип приложения — **Next.js**, версия Node.js — **22**.
3. Нажмите **Подключить аккаунт** у GitHub, разрешите доступ, выберите репозиторий
   `Bazhen-master/card` и ветку `main` → **Save**.
4. Включите **поддержку SSR**. Это обязательно: страницы читают базу на сервере, без
   SSR каталог и админка работать не будут. Выключить потом нельзя — только создавать
   приложение заново, поэтому проверьте этот переключатель до запуска.
5. Проверьте команды (обычно подставляются сами):
   - **Сборка:** `npm ci && npm run build`
   - **Запуск:** `npm start`
6. В разделе **Переменные окружения** добавьте три штуки, значения возьмите из своего
   `.env.local`:
   - `SUPABASE_URL` — Project URL из Supabase
   - `SUPABASE_SERVICE_ROLE_KEY` — секретный ключ из Supabase
   - `ADMIN_PASSWORD` — пароль для входа в `/admin`
7. Убедитесь, что стоит **Сборка по последнему коммиту** — тогда сайт пересобирается
   сам при каждом `git push`.
8. Нажмите **Запустить деплой**. Первая сборка занимает 3–5 минут, после неё в
   настройках приложения появится публичный адрес.

Порт задавать не нужно: `npm start` слушает порт из переменной `PORT`, её подставляет
платформа.

### Шаг 3. Проверка

Открыть сайт из России может только заказчица — попросите её зайти по адресу без VPN
и подтвердить, что видны каталог и картинки колод.

> Если сайт открылся, но пишет «База данных ещё не подключена» — он назовёт
> недостающие переменные прямо на странице. Добавьте их в **Переменные окружения**
> и пересоберите приложение.

### Render — запасной вариант

`render.yaml` остаётся в репозитории, и Render по-прежнему поднимет сайт через
**New → Blueprint**. Но как основную площадку его больше не рассматриваем:
доступность из России не гарантирована, а на бесплатном тарифе сервис засыпает и
первый запрос ждёт запуска 30–50 секунд.
