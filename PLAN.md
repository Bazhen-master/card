# План работы: Метафорические карты (пилот)

## Контекст

Открытая продажа колод метафорических карт любому желающему. Пилот без
маркетплейса третьих лиц — комиссию с чужих загруженных/сгенерированных карт
делаем отдельным этапом позже, сейчас НЕ реализуем.

Обновление 07.09.2026: «отдельный этап позже» назначен — это Этап 6 (аккаунты,
общая галерея, внутренний баланс). Пилот 1-5 остаётся работающим и без него.

## Модель данных

Использовать Supabase (Postgres + Storage) — закрывает и хранение картинок
(персистентно, в отличие от файловой системы хостинга), и базу данных.

```
cards
  id            uuid, pk
  deck_id       uuid, fk -> decks.id, nullable
  image_url     text        -- ссылка на Supabase Storage
  text          text, nullable  -- вопрос/фраза на карте
  source_type   enum('uploaded','generated')
  price         integer, nullable  -- цена поштучно, если продаётся отдельно
  created_at    timestamp

decks
  id            uuid, pk
  title         text
  description   text
  price         integer      -- цена всей колоды
  cover_image   text
  created_at    timestamp

leads                          -- для тестовой кнопки оплаты (Этап 4)
  id            uuid, pk
  deck_id       uuid, fk, nullable
  tariff        text          -- какой тариф выбрал
  contact       text          -- email/телефон
  created_at    timestamp
```

Автор/владелец карты и разделение выплат — НЕ добавлять в эту версию схемы
(зарезервировано на будущий этап). Этот будущий этап расписан ниже как Этап 6,
там же дополнение схемы: `profiles`, `purchases`, `balance_entries` и новые
поля `cards`.

Отклонение от схемы выше, внесённое на Этапе 2: в `decks` и `cards` добавлено
поле `sort_order integer not null default 0` — без него нельзя было выполнить
требование «сортировка» в админке.

## Стек

- Next.js (App Router) — уже развёрнут в этом репозитории.
- Supabase — БД + Storage + позже auth, если понадобится.
- Timeweb Cloud (App Platform) — хостинг, приложение Next.js с включённым SSR.
- Нейросеть для генерации: Kandinsky (FusionBrain API) — нужна пара ключей из
  личного кабинета заказчицы. Уточнение от 06.09.2026: сервис стал условно-платным.
  Бесплатная квота есть, но небольшая (по веб-интерфейсу — 20 изображений в месяц,
  по API называется около 100 запросов в месяц, официально подтвердить не удалось:
  fusionbrain.ai не открывается из-за рубежа). Точный тариф смотреть в кабинете.
  Следствие для Этапа 3: нужен общий месячный потолок генераций на весь сайт —
  лимита на одного посетителя при такой квоте недостаточно.

Решение от 07.09.2026: от FusionBrain (Kandinsky) отказались — дорого при
слабом качестве картинок. Новый поставщик — GenAPI (gen-api.ru), модель Flux
Schnell, 0,50 ₽ за картинку (колода из 60 карт — около 30 ₽); при
необходимости переключается на более дорогую модель одной переменной окружения.
Цена подтверждена настоящим списанием 07.09.2026, а не витриной тарифов: в
каталоге GenAPI указана базовая ставка сети, и она расходится с фактом в разы.
Оплата рублёвой картой, работает из России без VPN, один ключ на весь каталог
моделей. Код генерации переведён на сменного поставщика
(`lib/image-provider.js` + адаптеры в `lib/providers/`), чтобы следующий такой
переезд не стоил переписывания. Клиент FusionBrain оставлен как запасной.

Рассмотренные альтернативы: YandexART (~2,91 ₽ за картинку, официальный договор
и закрывающие документы, но сложнее регистрация и более «стоковый» стиль);
ProxyAPI с моделями OpenAI (качество высокое, цена для этой задачи избыточна).

Проверен nplod.ru («НейроПлод»), 07.09.2026 — НЕ подходит. Это сервис для
человека за браузером, а не для сайта: публичного API и документации для
разработчиков нет (ни раздела для разработчиков, ни упоминаний в их канале
t.me/nplod), тарифы видно только после входа в личный кабинет, внутренние
адреса вида /api/1/imageGenerator/requestGenerateImage работают по cookie
сессии — дёргать их с нашего сервера значит нарушать их правила и ловить
поломку при любой их правке. Как «сгенерировать картинки руками и загрузить
через админку» — годится, как источник для кнопки «Сгенерировать» на сайте —
нет.

Отклонение от исходного плана (05.09.2026): хостинг сменён с Render на Timeweb
Cloud. Причина — Render перестал открываться у заказчицы из России, а зарубежная
площадка не даёт на это повлиять. Заодно картинки карт больше не отдаются
браузеру напрямую с `supabase.co`: в вёрстке стоит `/api/image/<файл>`, файл из
Storage забирает наш сервер. Так у страницы остаётся ровно одна внешняя
зависимость от доступности — сам домен сайта. `render.yaml` оставлен в
репозитории как запасной вариант.

### Этап 6: Аккаунты, общая галерея и внутренний баланс

Заказан 07.09.2026. Пилот (Этапы 1-5) остаётся как есть и продолжает работать
без аккаунтов: посетитель без входа по-прежнему смотрит каталог и генерирует
карты по cookie-лимиту. Всё ниже — надстройка над ним.

**Что должно получиться словами заказчицы.** Посетитель заводит учётную запись,
видит историю своих генераций, может выставить свою карту в общую галерею с
ценой от 3 ₽ и может купить чужую. До покупки карта в галерее показывается с
полупрозрачным логотипом на всю картинку, после покупки — чистой.

#### Принятые решения (07.09.2026)

| Развилка | Решение | Почему |
| --- | --- | --- |
| Вход | E-mail + пароль, Supabase Auth, подтверждение почты пока выключено | Работает сразу, не требует ни своей рассылки писем, ни модерации на стороне VK/Telegram. Пароли хранит и проверяет Supabase, свой велосипед не пишем |
| Деньги | Внутренний баланс: пополнение крупной суммой, покупки списываются с него | Платёжная система берёт за операцию процент плюс фиксированную сумму — на прямом платеже в 3 ₽ площадка уходит в минус. Баланс — единственный способ оставить цену в 3 ₽ |
| Автору | Внутренние баллы без вывода: тратятся на генерации и покупки | Не маркетплейс: не нужны агентские договоры с каждым автором, чеки за них и проверка самозанятости. Деньги площадка получает вперёд, при пополнении |
| Галерея | Публикация после проверки в /admin | За чужие фотографии и запрещённый контент отвечает владелец площадки, а не автор |

Появится ещё одна переменная окружения — публичный (anon) ключ Supabase из того
же кабинета, что и service-role. Он нужен для проверки пароля при входе; в
отличие от service-role его не страшно отдавать браузеру, доступа к таблицам он
не даёт (RLS включён, политик нет). Данные, как и сейчас, читает и пишет только
серверный код.

> Из этого следует важное: пока баллы нельзя вывести, экономика замкнутая.
> Посетитель платит деньги площадке при пополнении, а внутри они ходят между
> авторами. Это осознанное ограничение пилота, а не недоделка, и его надо прямо
> написать в правилах публикации — иначе автор будет ждать выплату на карту.

#### Модель данных (дополнение к схеме выше)

```
profiles                      -- профиль поверх auth.users Supabase
  id            uuid, pk, fk -> auth.users.id
  display_name  text          -- имя автора под картой
  is_blocked    boolean default false
  created_at    timestamp

cards (добавить поля)
  owner_id      uuid, fk -> profiles.id, nullable   -- null у карт админки
  status        enum('private','pending','listed','rejected')
  price         integer       -- копейки, минимум 300 (3 ₽)
  preview_url   text          -- превью с водяным знаком, публичное
  reject_reason text, nullable

purchases
  id            uuid, pk
  buyer_id      uuid, fk -> profiles.id
  card_id       uuid, fk -> cards.id
  price         integer       -- копейки, цена на момент покупки
  created_at    timestamp
  unique (buyer_id, card_id)  -- дважды одно и то же не продаём

balance_entries               -- журнал движения баланса, источник правды
  id            uuid, pk
  profile_id    uuid, fk -> profiles.id
  delta         integer       -- копейки, со знаком
  kind          enum('topup','purchase','sale','generation','refund','admin')
  card_id       uuid, nullable
  comment       text, nullable
  created_at    timestamp
```

Баланс нигде не хранится отдельным числом — он равен сумме `delta` по журналу.
Так расхождение «на счету 12 ₽, а по операциям 9 ₽» становится невозможным, и
любой спор с автором разбирается по строкам журнала. Если суммирование окажется
медленным (это тысячи строк, не миллионы — вряд ли), кэш добавим отдельно.

**Деньги везде в копейках.** Существующие `decks.price` и `cards.price` хранят
рубли, их надо умножить на 100 разовой миграцией: комиссия площадки с карты за
3 ₽ в целых рублях не считается. В формах админки и на витрине цена остаётся в
рублях, копейки — только внутри базы.

#### Как работает водяной знак

Единственный надёжный способ — накладывать знак на сервере, отдельным файлом.
Полупрозрачный логотип, наложенный в вёрстке поверх картинки, снимается в
браузере за десять секунд, поэтому так делать нельзя.

1. Оригинал переезжает в **приватный** бакет Storage. Публичной ссылки у него
   нет вообще.
2. При публикации сервер делает превью: уменьшает картинку по длинной стороне
   (~700 px) и накладывает полупрозрачный логотип на всю площадь. Превью лежит
   в публичном бакете — его и видят в галерее.
3. Оригинал отдаётся через `/api/image/` только владельцу карты, покупателю и
   админу. Проверка — на сервере, по сессии, а не по ссылке.
4. Кнопка «Скачать оригинал» появляется на карточке только после покупки.

Инструмент — библиотека `sharp` (composite + resize). Риск: она собирается под
конкретную платформу, и на Timeweb App Platform это надо проверить в первый же
день работы над этапом; если не встанет — запасной вариант `@napi-rs/canvas`.

Логотип пока не согласован, поэтому первая версия знака — текстовая: название
сайта полупрозрачной надписью, повторённой по диагонали через всю карту. Способ
наложения от этого не меняется, меняется только то, что накладывается, так что
подстановка логотипа позже переделкой не будет.

## Правки по фидбэку заказчицы 08.09.2026

Разбор большого голосового отзыва. Мелкие правки и дефекты сделаны сразу, в
рамках пилота; новые функции вынесены в отдельные пункты и ждут согласования.

Сделано:

1. **Ссылка «Админка» убрана из шапки.** Первый приоритет заказчицы: она нашла
   тестировщицу и не хочет, чтобы посторонний видел служебный раздел. На доступ
   это не влияет — `/admin/*` и раньше был закрыт паролём в middleware, теперь
   владелица заходит по прямому адресу.
2. **Длина описания 500 → 2000 символов.** Ограничение не техническое: описание
   переводится на английский и уходит в Flux, чей текстовый кодировщик читает
   примерно первые полторы-две тысячи знаков. В подсказке под полем об этом
   сказано прямо, чтобы длинное сочинение не воспринималось как гарантия.
3. **Чужой запрос к нейросети больше не публикуется.** `cards.text` у карт
   авторов не выводится ни в галерее, ни на главной, ни на странице карты — и
   не подставляется в `alt`. Видит его только автор в кабинете и владелица
   сайта в `/admin/moderation` (там он был и раньше). У карт из колод каталога
   текст — подпись от владелицы, он остаётся на месте.
4. **Бесплатные генерации обнуляются в полночь по Москве.** Было скользящее
   окно в 24 часа от каждой генерации: нарисовал в 21:00 — жди 21:00 следующего
   дня. Заказчица ждала полуночи и справедливо удивилась. Смещение задано числом
   (UTC+3): в России нет перехода на летнее время, тянуть часовые пояса незачем.
5. **Комиссия площадки 30 % → 40 %.** Предложение заказчицы: автору 60 %,
   площадка зарабатывает в основном на генерациях. Изменено значение по
   умолчанию в коде; если `COMMISSION_PERCENT` задана в панели хостинга,
   значение оттуда важнее — там её тоже надо поменять.
6. **Квадратные карты не обрезаются.** В колоде карты показываются в своей
   пропорции и укладываются колонками (как в общей галерее) — раньше сетка
   резала всё под 3:4, и у мандалы срезало края, а край мандалы это часть
   рисунка. Обложка на странице колоды показывается целиком; в каталоге рамка
   обложек осталась 3:4 ради ровного ряда, но картинка внутри вписывается
   (`object-contain`), а не обрезается.
7. **Цену выставленной карты можно менять.** Новое действие
   `changePriceAction`: цена меняется у карты со статусом `pending` или
   `listed`, статус при этом не сбрасывается — повторной проверки не требуется,
   потому что модерация смотрит картинку, а не ценник. Раньше цену меняли
   только через «отозвать → выставить заново», то есть теряя место на витрине.
   Купленных карт это не задевает: в `purchases` цена записана на момент
   покупки.
8. **Таблички «скоро».** По отдельной просьбе: в каталоге — «Раздел в
   доработке», с обещанием авторских колод; на странице генерации — анонс
   выбора нейросети и правки готовой карты. Ни сроков, ни названий моделей в
   тексте нет намеренно: обещать конкретную сеть до её проверки нельзя.

9. **«Баланс: Бесплатно» при нуле.** `formatPrice` показывает ноль как
   «Бесплатно» — для цены это верно, для остатка на счету читается как ошибка,
   и видит это каждый сразу после регистрации. Суммы теперь идут через новую
   `formatMoney` («0 ₽»): баланс в кабинете и в `/admin/users`, остаток в
   подсказках на генерации и на странице карты, суммы в журнале операций. Цены
   как были, так и остались: карта за 0 ₽ — «Бесплатно».

- **Правка готовой картинки** («дорисовать птичку»): image-to-image или

## Доработки 08.09.2026: деньги, бонус, бесплатный период, названия карт

Пункты 8-10 из разбора фидбэка плюс две просьбы, пришедшие по ходу работы.

### Что сделано

**8. Отчёт `/admin/finance` — «сколько я заработала».** Настоящие деньги
отделены от внутренних баллов, и это главное в отчёте: пополнения — деньги,
полученные владелицей, комиссия и платные генерации — лишь уменьшение долга
перед авторами. Сложи их вместе — получится прибыль, которой нет. Расход
считается по всем генерациям, включая бесплатные: за них платит площадка
(`GENERATION_COST`, 0,50 ₽, переменная окружения, влияет только на отчёт).
Ниже — поимённо, кто и когда пополнял, и отдельным списком бонусы и правки.

**9. Стартовый бонус при регистрации.** По умолчанию 100 ₽, начисляется сразу
после создания учётной записи. Записывается как корректировка (`admin`), а не
пополнение: настоящих денег за ним нет, и в отчёте он не должен смешиваться с
переводами. Осечка бонуса не отменяет регистрацию — человек уже завёл
учётную запись, ронять её из-за подарка нельзя.

**10. Бесплатный период.** По умолчанию 7 дней от регистрации; дальше рисовать
можно только за баллы. У посетителя без учётной записи отсчёт идёт от его
первой карты: даты «прихода» у гостя нет, а без этого гостевой режим стал бы
дырой — аккаунт через неделю платит, а тот же человек без входа рисует
бесплатно всегда. Посетитель видит срок в кабинете и на странице генерации, и
формулировки разные: «на сегодня всё, новые после полуночи» проходит само,
«период закончился» — уже нет.

**Настройки в админке** (`/admin/settings`): бонус и длительность периода
меняются без правки кода и без передеплоя — заказчица просила «место, где
вбивать». Появилась таблица `settings` (ключ-значение). Там же показаны
значения, заданные переменными окружения (комиссия, цена и себестоимость
генерации), чтобы не искать их по панели хостинга.

**Название карты.** Автор пишет его при создании и меняет в кабинете; под ним
карта стоит в галерее и на своей странице. От `cards.text` отличается
назначением: text у сгенерированной карты — это запрос к нейросети, он чужим
не показывается, а название показывается всем. Свой запрос автор по-прежнему
видит в кабинете отдельной строкой.

**Убрана «Подписка на все колоды».** Решение заказчицы: сайт зарабатывает на
генерациях и поштучных картах, а подписка обещала посетителю то, чего в пилоте
не будет. Старые нажатия по ней остались в отчёте `/admin/leads` подписанными
(`TARIFF_LABELS`) — это уже собранная статистика, терять её незачем.
Подделанный `tariff=subscription` откатывается к покупке колоды.

### Миграция и порядок выкладки

Схему выполняет владелица сайта руками, а код приезжает деплоем сам — между
этими моментами сайт обязан работать. Поэтому:

- нет таблицы `settings` — действуют значения по умолчанию, страница настроек
  говорит, что выполнить;
- нет колонки `cards.title` — поля названия не показываются, и **ни один
  запрос её не просит**: прочитать несуществующую колонку нельзя, PostgREST
  отвечает ошибкой на весь запрос, и витрина осталась бы пустой. Выборки
  собираются функцией `withTitle()` по результату `cardTitleReady()`.

Миграция выполнена на живой базе 08.09.2026 («Success. No rows returned»).

### Прогон на живой базе

До миграции: все десять страниц отвечают 200, поля названия нет, настройки
работают на умолчаниях, сохранение отказывает с внятным текстом.

`curl -F` из Git Bash перекодирует кириллицу в значениях командной строки —

## Отказы генерации: что видит посетитель и что видит владелица (08.09.2026)

Заказчица спросила, какое сообщение выдаст сайт, когда на GenAPI кончатся
деньги, и подчеркнула: списывать с посетителя только за полученный результат.

**Списание.** Так и работало с Этапа 6.5 и не менялось: деньги снимаются до
рисования, но при любой осечке строка списания удаляется целиком — нет
картинки, нет и следа в журнале операций. Порядок именно такой намеренно: если
списывать после выдачи, человек с балансом на одну генерацию откроет две
вкладки и получит две картинки за одну оплату, а платит за них площадка.

**Что изменено.** Раньше посетителю показывался внутренний текст: «GenAPI:
Недостаточно средств», «проверьте GENAPI_KEY». Ему это не помогает, а название
поставщика и чужие финансовые дела знать незачем. Теперь наружу выходит одна
строка — «Не получилось нарисовать карту, деньги не списаны — попробуйте,
пожалуйста, написать в техподдержку», а настоящая причина уходит в лог
хостинга. Ошибки, которые посетитель может исправить сам (пустое описание,
слишком длинный текст, кончившиеся деньги на его балансе), помечаются `visible`
и показываются как есть.

**Невозврат.** Единственный случай, когда человек остаётся без карты и без
денег, — если не прошло само удаление строки списания. Сам он об этом не
узнает, поэтому в лог пишется намеренно кричащая строка с номером списания и
пользователя: по ней деньги возвращаются руками в `/admin/users`.

Прогон на живой базе со сломанным ключом GenAPI: посетитель увидел вежливый
отказ, баланс остался нетронутым, в логе — «Генерация не удалась: Сервис
генерации не принял ключ». Отдельно, временно сломав сам возврат, проверено,
что появляется строка «ВОЗВРАТ НЕ ПРОШЁЛ: списание <id> у пользователя <id>…»
и что списание при этом действительно остаётся. Поломка возвращена, возврат
снова работает. Тестовый аккаунт удалён.

## Комиссия на виду и «администратор» вместо «владелицы» (09.09.2026)

Две просьбы заказчицы.

**Слово «владелица».** В текстах для посетителя его больше нет: пополнение
баланса, недостаток средств на покупку и забытый пароль теперь адресуют к
администратору. Заодно ушли обороты вроде «напишите ей»: роль в тексте одна —
администратор, кто за ней стоит, посетителю знать не нужно.

**Комиссия.** Раньше её размер нигде не показывался, и автор узнавал о ней
только по сумме, пришедшей за продажу. Теперь процент и деньги названы прямо
там, где автор ставит цену:

- под кнопкой «Выставить в галерею» — «Минимум 3 ₽. Комиссия площадки — 40 %:
  с карты за 3 ₽ вам придёт 1,8 ₽»;
- под «Изменить цену» у выставленной карты — «Сейчас 5 ₽: комиссия площадки
  40 %, вам с продажи — 3 ₽», то есть по её настоящей цене;
- в блоке баланса — «деньги придут сюда за вычетом комиссии площадки».

Процент и суммы берутся из `COMMISSION_PERCENT` и `splitPrice` — тех же, по
которым идёт настоящее начисление. Отдельной константы для текста нет
намеренно: заказчица меняет комиссию переменной окружения, и подпись под
формой должна меняться вместе с ней, а не разъезжаться.

Живой прогон 09.09.2026: временный аккаунт с двумя картами (в галерее за 5 ₽ и
в кабинете) — подписи показали 40 %, 3 ₽ и 1,8 ₽, что совпадает с расчётом
`splitPrice`. Аккаунт и карты удалены.

## Почему карта иногда стоила 1 ₽ вместо 0,50 ₽ (10.09.2026)

Заказчица заметила в кабинете GenAPI, что часть генераций списывает 1 ₽ вместо
привычных 0,50 ₽, и предположила две причины: новая зарегистрировавшаяся
пользовательница тарифицируется дороже либо сработал какой-то суточный лимит.
Обе неверны — разобрано замерами:

- цена GenAPI не менялась: тот же запрос, что шлёт сайт (сеть `flux`, версия
  `schnell`, 768×1024), 10.09.2026 списал ровно 0,50 ₽;
- аккаунт и пользователь на цену не влияют, лимитов, повышающих ставку, у
  GenAPI нет вообще;
- дело в **формате карты**. GenAPI берёт за Flux Schnell 0,50 ₽, пока картинка
  меньше миллиона пикселей, и 1 ₽ после. Вертикальная 768×1024 и горизонтальная
  1024×768 — это 0,79 Мп, квадрат 1024×1024 — 1,05 Мп, то есть уже за границей.

Сверка с базой подтвердила: 09.09.2026 сделано 59 карт, из них 56 вертикальных
и ровно 3 квадратных, нарисованных в 20:56–20:58 МСК новой пользовательницей —
это и есть три строки по 1 ₽ в кабинете GenAPI.

**Исправлено:** квадрат в форме генерации теперь 960×960 (0,92 Мп) — замер
подтвердил 0,50 ₽. Сторона меньше на 6 %, на глаз разницы нет, превью в галерее
всё равно 700 px. Заодно снова стала верной себестоимость `GENERATION_COST`
(0,50 ₽): до правки отчёт в `/admin/finance` считал квадратные карты вдвое
дешевле, чем они обходились.

Правило на будущее: любое увеличение сторон проверять настоящим списанием.
Порог в миллион пикселей нигде в документации GenAPI не назван, и поле `cost`
в каталоге `GET /api/v1/networks` (4,5 ₽ у `flux`) с реальностью не совпадает —
верна только `cost` в ответе `GET /api/v1/request/get/{id}` после генерации.

## Защита админки

Без БД пользователей: пароль хранится в `ADMIN_PASSWORD` (переменная
окружения), middleware Next.js проверяет cookie/сессию перед рендером

или в git.
